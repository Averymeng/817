# 投放复盘诊断 Agent｜MVP 产品设计文档 v0.1

> 文档目的：使新的 AI、开发者或面试评审无需依赖历史聊天，即可理解本项目为什么做、完整产品如何扩展、本期做什么、Agent 如何工作、数据如何模拟、页面如何承载、如何评测与验收。

## 0. 决策状态

### 已确认

- 最终产品形态是多功能 AI 商业化销售工作台。
- 目标用户是广告平台商业化销售。
- 核心业务场景是销售定期为客户完成阶段性投放复盘，典型频率为每周一次。
- 真实产品每天从广告数据平台自动同步客户投放数据。
- 当前项目使用预先生成并保存的模拟客户数据，通过模拟接口复现每日同步。
- 第一版必须是能够自主决定诊断下一步的 Agent，而不是单次 Prompt 或纯固定 Workflow。
- Agent 必须覆盖账户整体、版位、计划、素材和转化链路，每一层都要分析；异常层级继续深入下钻。
- 当前客户数据是报告的首要依据。RAG 只召回经验，LLM 负责当前分析与案例差异推理。
- 销售可确认、修改、驳回或标记信息不足，反馈进入案例库。
- 案例反馈不仅包括当场审核，还应支持执行反馈和后续结果反馈。
- 网页报告未来需支持生成 PPT；二者共用结构化报告数据。
- 数据同步无需成为独立页面或核心按钮；用户通过客户与时间范围筛选查看相应数据。

### 待后续确认

- 首期具体模拟客户数量及行业分布。
- 投放平台是否严格模拟小红书聚光，还是使用平台中立字段。
- 指标阈值、行业基准与异常严重度的第一版口径。
- PPT视觉模板和导出实现排期。
- 完整工作台其他模块进入产品导航的先后顺序。

### 明确不做的虚假承诺

- 不宣称已经连接真实企业广告后台。
- 不宣称已有真实商业化销售用户。
- 不宣称 Agent 建议已带来 ROI、消耗或客资成本改善。
- 不使用无法解释来源的模拟指标冒充真实业务效果。

## 1. 项目背景与问题

广告平台商业化销售需要持续关注多个客户的投放情况，并定期向客户做阶段性复盘。实际工作通常需要拉取数据、核对指标、判断异常、比较账户/版位/计划/素材表现、分析转化漏斗、回忆历史经验、撰写报告、制作 PPT、与客户沟通并跟进建议执行。数据、报告和经验分散时，复盘高度依赖个人经验，重复工作多，判断过程难以沉淀。

项目来自真实的小红书商业化销售和成人教育客户复盘经历。历史材料可用于提取字段、人工分析逻辑和案例，但必须脱敏，且不能被描述为实时企业接入。

## 2. 完整产品愿景：AI 商业化销售工作台

完整产品不是单一报告生成器，而是围绕商业化销售工作周期构建的客户经营工作台。

| 工作域 | 需要回答的问题 | 典型能力 |
|---|---|---|
| 今日工作 | 今天最应该关注什么 | 客户异常、复盘任务、临期待办、业绩概览 |
| 商机开拓 | 哪些潜在客户正处于合适窗口 | 线索、业务信号、联网调研、优先级 |
| 客户经营 | 每个客户目前处于什么状态 | 档案、合作阶段、目标、跟进、投放状态 |
| 投放与复盘 | 客户投得怎么样、问题在哪里 | 数据查看、异常监控、Agent诊断、复盘报告 |
| 方案与行动 | 下一步向客户提出什么、如何推进 | 提案、优化建议、任务、客户反馈、结果跟踪 |
| 经验中心 | 过去哪些经验可以复用或应避免 | 案例、标杆、Badcase、规则、模板、评测样本 |

销售副驾是跨工作域的统一能力，不是与业务割裂的聊天页。它理解用户意图并调用已经建设完成的专业能力。

## 3. 完整工作台的模块评价（商业化销售视角）

### 必要且真实

1. **首页 / 今日工作**：销售管理多个客户，需要快速看到异常、复盘节点和紧急动作。
2. **客户经营**：所有投放、提案、复盘、行动和经验必须归属到客户，否则工作台会变成功能拼盘。
3. **投放与复盘**：直接服务客户经营、续约与增投，是最强业务核心。
4. **方案与报告**：商业化销售需要把判断转化成客户可理解、可沟通的交付物。
5. **行动与反馈**：没有执行和结果跟踪，报告无法形成业务闭环。
6. **经验中心**：销售经验和失败案例需要被检索、复用和用于评测。
7. **商机开拓**：符合销售职责，但与复盘链路相对独立，适合作为后续第二条深链路。

### 应合并而非独立堆页

- 跟进记录归入客户经营和行动，而不是独立“跟进记录”页面。
- 素材表现归入客户投放分析，不先建设独立素材库。
- 提案和复盘可共享报告仓库、版本、审核和导出能力。
- 早报是其他模块结果的聚合，不单独发展成复杂内容产品。
- 整页问答与全局浮窗共用同一销售副驾能力，不做两套逻辑。

### 暂缓或排除

- 自动调整预算和启停计划：越权且难以真实验证。
- 大而全CRM审批流：不属于个人商业化销售工作台的核心差异。
- 独立行业资讯门户、素材AIGC工厂、搜索词专项工具：可成为未来能力，但当前会分散主链。
- 多层抽屉和独立页面重复展示同一客户内容：增加状态和维护复杂度。

## 4. 本期 MVP 定位

### 一句话定义

面向广告平台商业化销售的投放复盘诊断 Agent：系统每日接收客户投放数据，在每周复盘或销售选定周期时，完整扫描账户、版位、计划、素材和转化链路，自主决定异常下钻、工具调用、追问、案例检索和停止；以当前客户数据为首要依据，结合历史案例差异生成有证据的复盘报告与优化建议，销售审核后的结论、修改、执行和结果反馈沉淀为下一轮可检索经验。

### MVP为什么选择这一条链

- 来自用户真实实习场景和历史材料。
- 任务发生频率明确，典型为每周。
- 存在复杂判断，LLM 和 Agent 有必要介入。
- 可以使用模拟数据完成离线评测和历史案例回放。
- 能形成“输入—自主分析—人工确认—经验回流”的闭环。
- 后续可自然连接客户经营、行动、报告、首页和经验中心。

### MVP暂不实现

- 商机发现、竞品监测、行业早报。
- 自动投放和真实账户写操作。
- 完整提案生成、素材生成、搜索词专项工具。
- 完整CRM、权限审批、企业微信和会议转写。
- 与核心复盘无关的空导航和空页面。

## 5. 触发与数据时间逻辑

必须区分数据同步频率和报告生成频率：

1. 广告平台每日自动同步数据。
2. 用户可按客户、当前周期和对比周期筛选查看。
3. 系统持续更新指标与异常状态。
4. 每周触发阶段性复盘任务，销售也可手动选择周期发起复盘。
5. 重大异常可在未来触发临时诊断，但不必自动生成完整PPT。

页面仅需显示“数据更新至 YYYY-MM-DD”以及同步缺失警告，不提供显眼的手动上传或同步入口。

## 6. MVP端到端主链

1. 模拟数据服务按日提供客户投放数据。
2. 用户选择客户、复盘周期和对比周期，或进入每周待复盘任务。
3. 系统校验数据完整性、字段口径和可分析范围。
4. 代码计算指标、趋势、漏斗、分层贡献和异常候选。
5. Agent完成所有层级的基础扫描与分层诊断。
6. Agent根据异常程度、指标冲突、业务影响和数据完整性决定深入下钻。
7. LLM基于当前客户数据、业务目标和工具结果形成初步诊断。
8. RAG检索可能相关的历史案例。
9. LLM比较当前客户与历史案例的相似点、关键差异和经验适用性。
10. Agent进行证据检查，决定输出结论、假设、追问或停止归因。
11. 系统生成结构化复盘结果，并渲染网页报告。
12. 销售逐条确认、修改、驳回或标记信息不足。
13. 保存Agent初稿、销售终稿和反馈原因。
14. 将审核结果存入案例库；后续可补充建议是否执行及结果变化。
15. 下一次诊断检索可引用案例，但必须重新比较差异，不能复制旧结论。

## 7. Agent自主性设计

### Agent可以自主决定

- 当前数据是否充分，是否需要追问。
- 本轮分析计划和工具调用顺序。
- 哪些异常值得进一步下钻。
- 下钻到哪个对象或转化节点。
- 是否检索案例、检索什么特征、是否继续检索。
- 案例是否真正适用。
- 证据是否足以支持结论。
- 何时输出、何时降级为假设、何时停止。

### Agent必须完成的固定任务

- 不得跳过账户、版位、计划、素材和转化链路的基础扫描。
- 每一层至少输出状态、关键指标、数据证据和判断。
- 必须记录本轮分析路径、工具调用、检索案例和停止原因，便于Tracing和评测。

### Agent禁止行为

- 编造数据、目标、行业基准或客户背景。
- 把相关性直接写成确定因果。
- 因召回案例相似而直接复制历史建议。
- 未经人工确认沉淀为标杆案例。
- 自动调整真实预算、启停计划或向客户发送报告。

## 8. 各技术能力的职责

| 能力 | 负责内容 | 不负责内容 |
|---|---|---|
| 代码 / 规则工具 | ROI、CTR、CPC、CPM、客资成本、趋势、环比、漏斗、异常候选 | 开放式原因解释 |
| Agent控制器 | 状态判断、分析规划、工具选择、下钻、追问、复核、停止 | 直接替代计算工具 |
| LLM | 当前情况理解、原因假设、案例差异推理、建议和报告表达 | 关键指标心算、虚构事实 |
| RAG | 从已授权案例中召回候选经验与证据 | 决定最终原因、机械复制建议 |
| 人工销售 | 审核、修改、客户沟通、执行决策和结果补录 | 被AI越权替代 |

### 诊断与案例的正确顺序

当前数据 → 代码计算和异常识别 → LLM形成当前问题初步诊断 → RAG召回案例 → LLM比较相似点与关键差异 → 修正/补充/否定初步诊断 → 证据复核 → 最终报告。

### 报告证据优先级

1. 当前客户真实/模拟输入数据。
2. 当前客户业务目标和用户补充背景。
3. 确定性指标和业务规则。
4. 已审核且有结果反馈的历史案例。
5. 已审核但暂无结果的普通案例。
6. LLM一般知识。

## 9. 全层级诊断设计

Agent必须全面覆盖，但不要求对所有正常对象生成同等长度的解释。

| 层级 | 基础扫描 | 可能的异常下钻 |
|---|---|---|
| 账户整体 | 消耗、预算、ROI、线索/成交、趋势 | 预算受限、整体掉量、结构变化 |
| 版位 | 信息流/搜索等消耗与转化贡献 | 版位效率、预算分配、量效冲突 |
| 计划 | 计划消耗、点击、转化、成本、稳定性 | 高消耗低转化、起量不足、波动异常 |
| 素材 | 消耗、曝光、CTR、转化、生命周期 | 素材疲劳、点击与承接不匹配 |
| 转化链路 | 曝光→点击→留资→有效线索→成交 | 主要流失节点、前后链路背离 |

固定扫描保证“不漏”，Agent下钻保证“有深度”。正常层级可在证据充分后停止；异常层级需要继续拆分对象、比较周期、检索案例或向用户追问。

## 10. 报告与PPT设计

### 统一结构化报告

网页和PPT必须消费同一份报告对象，建议至少包含：

- 客户、报告周期、对比周期、数据更新时间。
- 数据完整性和缺失说明。
- 核心结论摘要。
- 各层级状态与证据。
- 异常列表、严重度和业务影响。
- 可能原因、置信度和待验证假设。
- 历史案例、相似点、差异点和适用性。
- 优化建议、优先级、依据、风险和验证方式。
- 人工审核状态和销售终稿。
- 后续行动、执行状态和结果反馈。
- Agent运行版本、Prompt/规则/知识版本与Tracing引用。

### PPT建议结构

1. 封面：客户、复盘周期、报告时间。
2. 本周期核心结论。
3. 核心指标与趋势。
4. 全层级表现与异常定位。
5. 原因分析和数据证据。
6. 历史案例参考与关键差异。
7. 下一周期优化建议。
8. 风险、待验证项和行动计划。

当前先设计结构化字段和网页报告；PPT导出在主链稳定后实现，避免版式工作阻塞Agent诊断。

## 11. 人工审核、执行与结果反馈

### 第一层：当场审核（MVP必须实现）

- 采纳。
- 修改后采纳。
- 驳回。
- 信息不足。
- 保存修改后的最终结论及反馈原因。

### 第二层：执行反馈（首期预留，后续实现）

- 是否执行。
- 执行时间。
- 实际执行了哪一部分。
- 未执行原因。
- 下次观察时间。

### 第三层：结果反馈（首期预留，后续实现）

- 新周期指标变化。
- 效果改善、无明显变化或变差。
- 是否可能受其他变量影响。
- 是否升级为已验证或标杆案例。

### 案例状态

- 普通参考案例：已审核、暂无执行结果。
- 已验证案例：有执行记录和后续结果。
- 标杆案例：多次复用、结论可靠、效果相对明确。
- Badcase：诊断被驳回、建议无效或执行后效果变差。

当前没有真实投放环境，因此可完整验证第一层，后两层只做字段和交互预留；历史资料中确有结果时可如实补录，不得伪造。

## 12. 数据设计原则

### 数据来源层级

1. 少量真实脱敏历史材料：用于确定字段、异常模式和人工判断链。
2. 公开广告数据：用于补充常规分布和技术测试，需注明是否模拟。
3. 受控合成数据：用于制造明确异常、边界条件和评测标签。

### 初版核心对象

- 客户。
- 投放账户。
- 版位。
- 计划。
- 素材。
- 每日指标。
- 复盘任务。
- Agent运行记录。
- 复盘报告及版本。
- 审核反馈。
- 历史案例。
- 行动与结果反馈（可先预留）。

### 初版指标字段

- 日期、客户、账户、版位、计划、素材。
- 投放目标、预算、消耗、曝光、点击。
- 留资/线索、有效线索、成交量、成交金额。
- CTR、CPC、CPM、留资率、客资成本、成交率、ROI。
- 目标值、行业/客户历史基准、对比周期。

最终字段需根据历史材料再次核对。所有派生指标的公式和口径必须在数据合同中明确。

### 模拟数据要求

- 一次生成、持久化保存，不在诊断时随机变化。
- 固定随机种子和生成版本。
- 每个评测客户包含场景标签、预期异常和允许结论。
- 覆盖正常、单异常、多异常、缺字段、冲突证据、季节波动和无法归因。
- 数据在日期上连续，支持每日展示和周度聚合。

## 13. MVP页面与信息架构

MVP不使用四个彼此割裂的独立页面。建议采用“一主一辅”。

### 主工作空间：客户投放复盘

保持同一个客户和周期上下文，包含：

1. 客户、复盘周期和对比周期筛选。
2. 数据更新状态和缺失提醒。
3. 核心指标卡与趋势。
4. 账户、版位、计划、素材和转化链路分析。
5. Agent分析状态、路径和工具调用摘要。
6. 异常定位、证据、原因和待验证假设。
7. 历史案例、相似点、关键差异和适用性。
8. 网页报告与PPT结构预览。
9. 逐条审核、修改、驳回和反馈原因。

上述内容可以使用分区或内部Tab，但不能让用户在多个页面中反复丢失客户和时间上下文。

### 辅助入口：历史案例库

- 按客户、行业、异常标签、审核状态和案例等级筛选。
- 查看原始数据摘要、Agent初稿、销售终稿和反馈。
- 查看执行与结果状态。
- 显示案例可否被RAG引用。

### 完整工作台中的位置

未来主导航可扩展为：首页、商机、客户、报告、行动、经验；当前未达到可用标准的模块不显示为空页面。MVP主工作空间未来归入“客户 > 投放与复盘”，案例库未来归入“经验”。

## 14. 评测设计

### 评测对象

- 字段校验与缺失识别。
- 指标计算正确性。
- 全层级扫描完整性。
- 异常定位准确性。
- Agent路由和工具选择。
- 当前诊断的数据忠实度。
- RAG召回相关性。
- 案例差异识别与经验适用性。
- 建议可执行性、风险意识和业务适配。
- 证据不足时的追问、降级和停止。

### 第一版评测集

- 先建立20条可运行案例，后续扩展到30—50条稳定复测。
- 案例覆盖正常、单异常、多异常、数据缺失、冲突、季节性、无可用历史案例和相似案例误导。
- 每条案例记录：输入、预期扫描、预期异常、允许结论、禁止结论、应调用工具、应否检索、停止条件和评分标签。

### 评测方式

- 代码测试确定性计算。
- 人工评分诊断和建议。
- LLM-as-a-judge初评，人工抽检校准。
- 历史案例回放：隐藏前辈人工结论，让Agent独立分析后比较。
- 保存Badcase的现象、根因节点、修改动作和同口径复测结果。

### 无真实用户时的表达

可以表述为“离线评测、模拟用户任务、历史案例回放、专家/从业者评审”；不得表述为真实上线、真实客户采纳或业务指标提升。

## 15. 实施计划与版本边界

### 阶段0：设计冻结

- 确认完整工作台蓝图和MVP边界。
- 从历史材料抽取真实业务规则。
- 确认数据合同、Agent状态机、报告JSON和评测标准。
- 输出页面线框与设计规范。

### 阶段1：非LLM底座

- 建立模拟数据生成器和持久化数据。
- 实现客户/周期筛选、指标计算、趋势、漏斗和分层表。
- 建立报告、运行记录、反馈和案例的数据结构。
- 用固定模拟结果完成主工作空间页面。

### 阶段2：Agent主链

- 实现数据校验和固定全层级扫描。
- 实现Agent规划、工具调用、异常下钻和停止。
- 实现当前客户初步诊断。
- 实现RAG案例召回和LLM差异比较。
- 实现证据校验和结构化报告。

### 阶段3：人工反馈与案例闭环

- 实现逐条确认、修改、驳回和原因。
- 保存Agent初稿、销售终稿和版本。
- 审核结果进入案例库并可被后续检索。
- 预留执行和结果补录。

### 阶段4：评测与稳定

- 建立20条初版评测集。
- 运行链路级和端到端评测。
- 分类Badcase、修改节点、同口径回归。
- 记录Prompt、模型、规则、知识和数据版本。

### 阶段5：PPT与完整工作台扩展

- 将结构化报告渲染为PPT。
- 再按业务价值依次建设客户经营、行动、首页聚合、商机开拓等模块。
- 新模块达到最低可用标准后才加入导航。

## 16. MVP验收标准

1. 系统可从持久化模拟数据中读取连续每日数据，并按客户和周期切换。
2. 所有确定性指标计算有公式、口径和自动化测试。
3. Agent每次都覆盖账户、版位、计划、素材和转化链路。
4. 异常层级能够继续下钻，正常层级能够有证据地停止。
5. 缺失或冲突数据不会被编造，Agent能追问、降级或停止。
6. 初步诊断首先依据当前数据，不先套历史案例。
7. RAG返回候选案例后，LLM能说明相似点、差异点和适用性。
8. 每条重要结论和建议可以追溯到输入数据、规则或案例证据。
9. 用户可以逐条确认、修改、驳回或标记信息不足，并保存原因。
10. Agent初稿、销售终稿、反馈和案例状态均可再次查看。
11. 下一次诊断能够检索审核案例，但不会机械复制历史结论。
12. 网页报告结构可稳定映射到预定PPT章节。
13. 20条初版评测案例可重复运行并保存结果。
14. 界面不出现未完成的空页面，客户和时间上下文不因切换分析区而丢失。

## 17. 新AI开始实施时的强制复述清单

开始任何任务前，新的AI必须回答：

1. 完整工作台愿景与当前MVP分别是什么？
2. 为什么数据每日同步而报告典型为每周生成？
3. 为什么模拟数据不能在每次诊断时临时随机生成？
4. 哪些步骤由代码、Agent控制器、LLM、RAG和销售分别完成？
5. 为什么所有层级必须扫描，但异常层级才继续重点下钻？
6. 为什么必须先分析当前客户，再检索和比较历史案例？
7. MVP的主工作空间和案例库如何组织？
8. 报告与PPT为什么必须共用结构化数据？
9. 当前可以证明哪些效果，不能宣称哪些效果？
10. 当前唯一任务、允许修改文件和禁止修改范围是什么？

复述未通过时不得开发。
