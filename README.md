# 817｜AI 商业化销售工作台

面向广告平台商业化销售的 AI 客户经营工作台。完整产品围绕每日工作、商机开拓、客户经营、投放复盘、方案与行动、经验沉淀展开；当前第一阶段只深度实现“客户阶段性投放复盘 Agent”闭环，其余模块作为完整产品蓝图逐步建设。

## 当前项目状态

- 当前阶段：MVP 设计冻结前的第一版基线。
- 核心用户：广告平台商业化销售。
- 核心任务：销售定期（典型为每周）为客户完成阶段性投放复盘。
- 数据方式：真实产品每日从广告数据平台自动同步；本项目使用预先生成、持久化保存的模拟客户数据，通过模拟接口复现自动同步。
- AI 形态：第一版即为有明确边界的诊断 Agent，不是单次 Prompt 报告生成器。
- 真实性边界：项目可以证明离线诊断、历史案例回放、人工审核和 Badcase 迭代，不能宣称真实企业接入、真实用户使用或 ROI 提升。

## 新对话 / 新 AI 接管顺序

1. 完整阅读根目录 `AGENTS.md`。
2. 完整阅读 `docs/MVP_DESIGN.md`。
3. 检查当前 Git 状态、最近 5 次提交和项目目录。
4. 用中文复述：产品定位、完整蓝图、本期 MVP、Agent 自主边界、数据边界、已确认页面、当前任务和禁止扩展内容。
5. 在用户回复“理解正确，可以开始”前，不修改代码、配置、数据或文档。

## 核心文档

- `AGENTS.md`：所有后续 AI 必须遵守的协作、开发、验收和 Git 规则。
- `docs/MVP_DESIGN.md`：当前 MVP 的完整产品设计、AI 链路、数据、页面、评测与实施计划。

## 当前一句话定义

投放复盘诊断 Agent 每日接收广告平台同步的客户数据，在销售选定复盘周期或每周任务触发后，完整扫描账户、版位、计划、素材和转化链路，自主决定异常下钻、工具调用、追问、案例检索和停止条件；它以当前客户数据为首要证据，结合历史案例差异生成可审核的网页报告与 PPT 结构，销售确认、修改或驳回后沉淀反馈，为下一次诊断提供可追溯经验。
